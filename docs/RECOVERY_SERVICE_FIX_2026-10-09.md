# 工作台恢复无效：排查与修复（2026-10-09）

## 实际问题

用户点击恢复并确认 Yes 后，服务已接收请求，但后台恢复线程失败：
`Workcell recovery failed: 'NoneType' object has no attribute 'success'`。
这不是未确认，也不是按钮没有发送请求。

场景桥默认等待服务 5 秒。连接器超时可能返回空 payload，桥接代码
直接访问 `response.payload.success`，导致恢复中断。旧日志没有记录具体
超时服务名，因此不能断言当时是哪一次生成或删除调用超时。
界面又把恢复失败原因覆盖成通用确认提示，使操作员看不到真实错误。

## 修复内容

- RAI `src/rai_sim/rai_sim/o3de/o3de_bridge.py`：先检查空响应，报出具体
  服务名和等待时间。生成/删除超时意味着执行结果未知，不盲目重发，
  不擅自删除实体跟踪记录。其他调用者仍默认等待 5 秒。
- 工作台 `runtime.py`、`config/workstation.yaml`：场景服务等待时间单独
  配置为 20 秒；清理时逐个删除实体，避免部分删除成功后遇到缺失实体，
  却错误处理最初记录的实体。只有明确回复实体不存在才清除对应记录。
- `operator_panel.py`：保留后台返回的场景恢复失败原因，不再被通用确认
  说明覆盖。

## 验证

- RAI 场景桥单元测试：13 项通过，包括超时不重发、跟踪保留和显式拒绝重试。
- Qt 面板测试：42 项通过，包括恢复错误提示不被覆盖。
- 场景清理回归测试：1 项通过，覆盖先成功删除、随后遇到缺失实体。
- 工作台包 colcon 构建成功。
- 重启仿真和面板后，实际调用 `/produce_orders/recover` 一次：
  `READY → RECOVERING → READY`；服务确认开始恢复，随后实际状态回到
  “场景已重置，库存已就绪”。未提交新订单。

## 操作影响与边界

本次完整重启清除了内存订单队列、失败箱绑定及失败现场，磁盘上的历史
订单报告保留。恢复服务验证覆盖无执行任务时对当前库存场景的清理重建；
没有新跑抓取订单，也不代表视觉漏检问题已经解决。
即使调整等待时间，严重卡顿时仍可能超时，此时应显示明确服务错误并停下，
不能把未知物理结果当成功。

改动涉及 RAI 主仓库和 manipulation-demo 嵌套仓库，分别提交。
