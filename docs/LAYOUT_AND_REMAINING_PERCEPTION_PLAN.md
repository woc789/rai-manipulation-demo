## 2. 剩余原因与处理方向

### A. 类别混淆：已确认，优先解决

同一 RGB 图像查询 apple / tomato 时返回大量重合框，四类商品的视觉外观
不足以被现有单类文字查询稳定区分。8 个 apple 框不等于 8 件苹果库存。

先在现有框架测试四类联合检测（在实际服务中传逗号分隔类别，模型内部
转换为句点分隔提示），避免每次单独询问让同一物体重复匹配不同类别。
保存类别冲突而不双重承诺库存。联合提示效果必须同图对照，不能保证一定改善。
如仍混淆，为候选图块增加四类二次分类器，使用当前仿真画面的已核对样本训练。
数据生成可用仿真真值作离线标签，运行时必须仍由图像给出类别，不把实体名传给 Agent。
拒绝不确定类别，保留现有安全核对。不要只靠颜色规则，也不要直接放宽安全阈值。

### B. RGB / 深度未同步：已确认存在时间差

实测约 0.10～0.13 s，当前依次读取图像，没有同步配对。静态桌面未必导致
明显错误，但运动中可能导致掩码与深度位置不匹配。

增加有界缓存的同步采集器，用 message_filters 的时间同步/近似时间同步；
统一与相机发布端兼容的 QoS，使用消息时间戳而不是接收墙钟。
检查新鲜度、图像尺寸和相机内参，超出容差则重新取帧，等待超时应明确报错。
TF 查询使用对应图像时间，不能总取最新变换来处理旧图像。
建议先测时间差分布后确定容差，不直接拍脑袋设置一个大容差吞掉错配。

### C. 分割、深度与抓取点偏差：需要分层验证

目前已具备 box / mask / cloud / position 数量诊断，不能因最终空候选
就断言模型没有框。对 box>0、cloud=0 的记录检查掩码、有效深度比例和形状。
使用稳健点统计、桌面点剔除和物体表面抓取点，不盲目把整个点云均值作为抓取点。
固定胡萝卜补偿偏移具有当前场景限制，换布局后要观察不同位置误差，不直接扩大补偿。

### D. 规则过滤和库存身份关联：已存在，不等同于漏检

候选可能被箱位、放置目标、安全分类核对或资源所有权过滤。
查看 PERCEPTION_PIPELINE 与 PERCEPTION_RESULT，先找丢失层再改规则。
库存关联应结合位置误差、时间和执行轨迹；类别冲突对象标为不确定而非同时承诺。
不扩大关联半径到会合并两个相邻实物的程度，不放行其他订单资源。

### E. 持续遮挡：布局只能缓解

如果新布局仍在机械臂工作姿态下遮挡，应增加经 MoveIt 验证的观察姿态，
只在夹爪空、单件装箱并退出的安全边界执行，然后等待新鲜同步图像。
观察动作也需要 Action 反馈、取消与超时。第二固定相机为后续备选，不能
用“看不到但仿真知道”的物体坐标补齐工具输出。

## 3. 下一步建议

先做同步采集器与类别联合检测的同图对照；两项分别修改、验证，避免无法归因。
同步采集改善坐标可靠性，不承诺改善 apple/tomato 分类。
类别混淆若持续，二次分类/四类专用模型是正面处理方式，而非无限重试。
观察姿态仅在布局复测仍存在明确遮挡时增加。

## 5. 玉米识别修复与实际订单验证（最新）

### 痛点定位

问题不仅是视觉漏检：此前边缘玉米的生成位置x=0.201，落稳后实际x分别
约0.189和0.199，越出工作区。即使视觉产生框，也会被既有安全规则拒绝。
同时整图缩放后玉米较小，当前GroundingDINO对四根玉米不能稳定产生框。
不能通过放宽工作区或把仿真坐标塞进检测结果解决这些问题。

### 布局修改

玉米1/4改为前景箱位之间的(0.560, -0.0525)/(0.560, 0.0525)，
玉米2/3维持(0.326, 0.539)/(0.220, -0.347)。采用平放朝向，不改物体大小。
中间曾试x=0.590，实际落稳向前漂移约12mm使其超出x=0.600；最终改为0.560。
当前四根实际落稳x约0.572、0.324、0.220、0.573，均在工作区。
布局测试增加边界余量检查，但测试不能替代实际落稳位置复核。
只补货更新剩余桌面物品，保留A1/A2已完成的订单箱，不自动确认取货。

### 感知修改及模块上下游

`workstation.launch.py`通过环境变量`RAI_GDINO_TILE_CLASSES`为本工作站
启用玉米分块检测。其他未配置调用方默认仍走原来的单图检测。

主仓库`run_perception_services.py`声明tile_classes、tile_rows、
tile_columns、tile_overlap参数；`detection_service.py`在请求到来时
把参数交给`GDBoxer.configure_tiling()`，不改变检测服务消息接口。

`GDBoxer.get_boxes()`先保留原整图检测，再对选定类别进行3×3均匀分块，
相邻图块重叠25%，最多9块。这样小物体在每个模型输入中占据更大比例。
检测阈值仍为box=0.35、text=0.45，模型权重仍为原GroundingDINO。
跨内部切块边缘的残缺框不采用；恢复图块像素偏移，再用同类IoU>=0.5
去重。返回的依然是相机图像框，不是三维真值。

下游保持原链：检测框→SAM掩码→深度点云→TF变换→工作站候选过滤→
Agent选择→运动Action→MoveIt→装箱核验。没有把生成坐标传给Agent，
仿真实体TF仅用于事后独立核对识别误差及原有执行安全检查。

### 代价、部署与限制

分块增加推理次数，当前一次完整玉米定位约18秒，不是更快的检测。
最多3×3块、有界重叠，复用现有模型，没有额外常驻模型占用。
ROI与整图分支都可能执行分块；其他未选定类别不增加分块推理。

为保留运行中的箱子和订单，本轮仅重启感知进程，通过临时用户服务
`produce-order-perception.service`运行修复版本。它随主工作站停止；
以后完整启动由已修改的launch为原感知启动流程启用同样参数。
当前使用本地模型缓存和离线模式，无权重下载。

RGB与深度时间差、苹果/番茄类别混淆及跨观测重复身份仍是剩余问题；
本轮没有宣称这些已修复。新布局在其他机械臂姿态/更多箱子下的稳定性
也需后续观察，不能把一次订单成功当作所有状态下的识别保证。
