# 视觉漏检改进与诊断（2026-10-09）

## 必须纠正的排查结论

最初仅检查 GDBoxer 外层的 BGR→RGB 转换，错误地认定相机 rgba8 红蓝通道颠倒
就是漏检根因。进一步检查已安装 GroundingDINO `Model.predict_with_classes`
与 `Model.preprocess_image` 后确认：接口接收 BGR，内部再次转 RGB。
原 rgba8 图像的两次转换最终抵消，因此不能将当前 rgba8 漏检归因于颜色颠倒。
原代码对本来就是 bgr8/bgra8 的输入仍有风险，现已统一使用 CvBridge
`desired_encoding="bgr8"`，移除外层不明确的色彩转换。
不同编码的同一图像应向 Model 传入完全一致的 BGR 数组。

## 实施的改善

1. `gripping_points.py` 增加可选的归一化桌面检测 ROI。
   当前固定 RGBDCamera5 使用 `[0.20, 0.36, 0.80, 0.80]`。
2. 工作台开启 `include_full_frame`：同一 RGB 帧分别进行 ROI 与全图检测。
   ROI 检测框先加回裁剪偏移，随后与全图检测框按 IoU >= 0.5 去重合并。
   不用仿真实体标签或坐标补齐检测。
3. SAM 使用原始完整 RGB 图像与已还原的检测框；深度图和相机内参保持
   原始完整尺寸，因此无需修改内参，也不能拿局部像素直接反投影。
4. 每次定位记录检测框数量、分数、分割数量、有效点云数量、最终定位数量、
   输入编码、原始尺寸、RGB/深度时间差及失败阶段。
5. 工作站继续记录空间/箱位排除、之前的分类安全拒绝、重复候选、目标间距、
   预留归属等过滤计数。定位到了但全被过滤时，不再只当作模型没检出。
6. 空结果时保存当前相机证据图到
   `~/.local/share/produce_order_workstation/perception/`，路径进入事件与订单报告。
   保存图像失败只记录诊断错误，不覆盖原执行结果。
7. 保留阈值、安全分类核对、有限重试及总预算；没有为完成订单强行放宽它们。

## 当前输入输出

RGB / Depth / CameraInfo → 全图与桌面区域检测 → 原图坐标合并去重
→ 原图 SAM → 原始深度与内参生成点云 → TF → 三维定位
→ 工作站安全/库存过滤 → Agent 的候选列表。

`PERCEPTION_PIPELINE` 是模型到定位的诊断事件；`PERCEPTION_RESULT` 是
业务过滤后结果。空结果的 `empty_stage` 与 `filtered_counts` 用于定位失败层。
没有加入新的 Agent 工具、权重或依赖，没有自动提交测试订单。

## 尚未解决的边界

- 苹果与番茄仍有明显类别混淆；裁剪增加框不等于提高分类精度。
- 两个尺度合并可能保留错误类别框，仍须原有安全拒绝机制。
- 固定相机 ROI 随场景布局/相机变更必须重新核对，或设为 null 禁用。
- 一次定位新增一次检测推理，增加耗时，但只做有限的两次，不无限扫描。
- 相机遮挡未消除；本次未增加机械臂观察姿态或第二相机。
- RGB/深度目前只记录时间差，未实现同步订阅；真实测试出现约 0.10～0.13 s
  偏差，静态桌面可用于本次观察，但不能据此保证动态物品定位可靠。
- 没有完成真实抓取整单验收，不能宣称漏检已彻底解决。
