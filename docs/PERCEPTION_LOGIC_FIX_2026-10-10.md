# 检测链路逻辑修复（2026-10-10）

## 范围与边界

保持 GroundingDINO、SAM、模型 API、现有布局和检测阈值不变。本次修复的是检测结果进入业务和执行模块之后的处理逻辑，不代表视觉模型准确率已经提高。

仿真实体类别/位置仍只用于原有安全核验与装箱验证；Agent 接收的候选和机械臂抓取目标仍来自 RGB-D 检测、分割、深度与 TF，并应用现有标定。没有改成已知坐标抓取，也没有关闭 MoveIt 碰撞检查。

## 上下游联动

`ProduceAgent → Workstation.get_object_positions → InventoryLedger.observe/reserve → Agent 选择 detection_id → Workstation.pick_and_place → 运动 Action / MoveIt → 装箱验证 → 库存与订单提交`

1. **库存关联（inventory.py / InventoryLedger）**：Workstation 现在传入配置中的关联半径和有效期，不再一边使用默认 3.5 cm、一边使用运行时 6.5 cm。关联使用水平距离并独立限制高度差，减少表面高度抖动造成的重复身份。丢失的预留物品仍保留所属订单且进入 UNKNOWN；仅局部身份不明的新增候选隔离，不再因为一个预留目标丢失否定全桌新候选。这不是外观跟踪，无法可靠关联任意大幅移动的物品。
2. **候选过滤（runtime.py / Workstation）**：配货模式只排除实际生成的箱子，不把四个空箱位模板都视为实体障碍。安全拒绝改为同类别、2 cm、20 秒的局部冷却，不再整单永久屏蔽 6.5 cm 范围；保留原因码与过滤计数。
3. **坐标使用（Workstation.pick_and_place）**：新鲜候选在 8 秒窗口内复用；任何实际运动开始即失效。过期后才重新检测，并限制位置关联距离、拒绝近似等距的歧义目标。候选不是一个新的物理定位传感器：当前时间标记是检测完成时间，并非完整的相机采集时间契约，长期仍应改成结构化、带时间戳的观测。
4. **放置目标（Workstation._placement_target）**：保留 12 cm 源—目标间距与既有数量上限。首选放置点不合适时，尝试箱内四个确定性偏移；保留已使用的位置并在暂停上下文中恢复，避免直接否定源目标或重叠放置。
5. **Agent 反馈（agent.py / ProduceAgent）**：PerceptionMismatch 提供 reason_code/reobserve。仍有可用 ID 时先尝试其它候选，不强制再跑整条视觉链；无可用 ID 才重新观察。连续候选拒绝有上限（沿用配置中的五次），避免非空误检导致无限循环。成功装箱才重置计数。
6. **安全暂停（runtime.py、scheduling.py、order_server.py）**：区分“以前运动过”和“当前物理状态尚未确认”。已经完成放置、退出并核验后，后续感知/业务异常保留已完成数量并进入人工复查暂停；调度器排除这类暂停单，不立即重试。操作员点击“视觉复查”，扫描成功后才解除复查门禁并重新校验资源。运动中断、搬运/放置未核验或最终物理审计失败仍走失败/恢复，不自动续抓。
7. **界面（operator_panel.py）**：复查暂停显示“等待人工复查 · 保留进度”，不当成普通排队名次。复用现有视觉复查、丢弃部分订单与恢复入口。
8. **超时报错（主项目 rai.tools.timeout）**：工作函数自身抛出的 TimeoutError 不再被误报成外层 180 秒截止。保留真实服务错误；并未强制杀死后台线程或取消所有 ROS 请求。

## 配置

`ros2_ws/src/produce_order_workstation/config/workstation.yaml` 新增：

```yaml
inventory_ttl_s: 60.0
visual_freshness_s: 8.0
rejection_radius_m: 0.02
rejection_cooldown_s: 20.0
```

这些参数在 perception 节点下。提高复用时间或关联半径不是免费的稳定性提升，会增加错误关联风险。

## 验证与使用

新增 `test/test_perception_logic.py`，覆盖半径配置、高度抖动、局部隔离、冷却到期、检测别名回退、真实箱位过滤、新鲜结果复用、安全暂停、运动失败及新增商品校验。既有库存/调度/订单 Action 加新用例共 **100 项通过**。

新增 `scripts/verify_perception_logic.py` 是显式仿真验证入口：通过正常 SubmitOrder 服务登记订单，监听订单事件和工作台状态；有在用箱子/未完成订单时拒绝覆盖。失败或人工复查时停止批次，不自动恢复、不重复提交、不用仿真真值代替检测。

```bash
python3 ros2_ws/src/produce_order_workstation/scripts/verify_perception_logic.py \
  --order corn=2 --order carrot=1 --order apple=1,tomato=1
```

请在现有 ROS 工作站环境中执行。会真实调用大模型 API 并移动仿真机械臂。报告位于 `~/.local/share/produce_order_workstation/reports/logic-*-batch.json`，完成箱保留等待取货。

### 首次实测

订单 `logic-20261010-222932-1`（玉米 2 件）：108.42 秒后失败，完成 0/2。视觉调用 1 次，返回 3 个原始三维候选、2 个属于该订单的可用 ID；Agent 选择后直接进入抓取，没有额外重检测，没有候选安全拒绝或空检测重试。

失败原因是 **MoveIt 无法找到无碰撞的抓取/接近/转运组合**。诊断快照显示带碰撞检查的 Cartesian 完成率 0.1、不检查碰撞时 1.0；这支持碰撞约束是限制因素，但不能据此断言是哪一个障碍或排除自碰撞。系统没有执行不检查碰撞的轨迹。后续测试批次停止，随后通过正常恢复服务恢复本次测试现场。

这证明“本次玉米检测→库存预留→Agent 选择→开始抓取”的链路贯通，不证明玉米订单成功，也不是统计漏检率对照。

- `logic-20261010-223616-1`：胡萝卜 1 件，70.09 秒完成 1/1，进入 WAITING_PICKUP。视觉调用 1 次，候选拒绝 0 次，空检测 0 次；完成了实际抓取、放置、退出和审计。
- `logic-20261010-223616-2`：苹果 1 件＋番茄 1 件，78.78 秒后完成 0/2，五次 CLASS_CONFLICT 后停止。视觉管线调用 7 次（包括别名尝试），没有空检测，没有误抓。苹果候选实际落在其它类别物品附近；这不是“没检测框”，而是类别误检被安全核验拦截。20 秒冷却过期后仍可能再次产生相同误检，五次总上限保证退出，但不保证视觉分类纠正。

两批真实报告：`~/.local/share/produce_order_workstation/reports/logic-20261010-222932-batch.json` 和 `logic-20261010-223616-batch.json`。这些是小样本功能检查，不是修改前后的漏检率统计。第二轮扩展回归 **86 passed、1 skipped**；Qt 面板用例因该测试解释器缺少可用 Qt 依赖跳过，未声称经过该环境自动化验证。

测试完成后通过正常确认取货接口收走测试胡萝卜订单；最终重启工作站以加载后补的超时/提示与最终审计保护修复。没有清除用户订单报告。场景重建会清理本次仿真测试物品，测试 JSON 保留。

## 尚未解决

- GroundingDINO 本身误检、遮挡、小目标和漏检没有因为这些逻辑修复消失。
- 三维位置空间关联仍不是可靠的多物体外观跟踪；丢失或大幅移动后应保持不确定。
- Agent 仍按订单类别顺序处理，尚未实现基于观察的动态选品次序。
- 尚未建立完整的相机采集时间、检测置信度、分割质量、坐标协方差消息契约。
- 仿真安全真值校验无法直接照搬到真实机器人，需要视觉/夹爪/称重等真实反馈替代。
- 当前实测暴露的不可达/碰撞规划问题与漏检应分开处理；不能为了订单成功放开安全约束。
