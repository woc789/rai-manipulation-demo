# 多订单队列可见性与记录清理

日期：2026-10-09。范围为原方案第2、3步的操作闭环，不修改Agent、运动或库存算法。

## 原问题

队列藏在底部“任务调度”标签页，当前执行任务与新提交任务容易混淆。
登记成功只写入通用通知，后续日志会覆盖；订单记录将诊断JSON也列为订单。
已有取消排队接口，但缺少清晰的选中目标、请求中状态与操作反馈。

## 修改

- `operator_panel.py`：把队列表移到任务进度与箱位之间，主页面直接显示。
  显示订单、优先级、状态、进度、等待原因、排序顺位和商品。
  执行中的任务置顶；待处理订单按优先级降序，同级保留服务端登记顺序。
  顺位表示排序位置，不保证等待库存的第一单一定最先执行，资源检查仍由服务端负责。
- 下单区域增加独立登记回执。提交中、登记成功、拒绝及超时未确认明确区分。
  执行中提交新订单不会覆盖当前机械臂任务；迟到的服务端队列快照可确认超时登记。
  不将点击提交或本地草稿当作已登记，不伪造队列条目。
- 排队取消按钮单选订单，显示请求中状态；仅服务成功响应后移除已取消行。
  拒绝或超时恢复按钮，保留原订单等待核对。暂停订单使用明确的丢弃确认流程。
  批量清队列仍复用服务端取消校验，不取消执行中或部分装箱订单。
- 订单记录页新增“清除已结束记录”和“恢复显示”。只清理界面显示，原始JSON报告、
  取货凭据和服务器订单号去重依据均保留，不释放库存或箱子。
  活动订单、暂停、待取货以及仍占用需恢复箱位的订单不能隐藏。
  隐藏名单保存在报告目录的`.panel_hidden_orders.json`，原子替换，界面重启后保持。
  诊断JSON不再作为订单记录显示，保留最近50条真实可见订单记录。

## 操作

1. 执行中也可填写下一单，点击提交，观察下单区“已登记：订单号”。
2. 对照主界面队列表的同一订单号、商品及等待原因；未确认时不要换号重复下单。
3. 选中待执行行，再点击“取消选中排队单”；当前正在执行订单使用任务卡上的取消按钮。
4. 批量取消使用“清除待执行队列”，确认对话框提示保留活动/部分装箱/待取货任务。
5. 底部订单记录页“清除已结束记录”仅清界面历史；“恢复显示”可恢复。
