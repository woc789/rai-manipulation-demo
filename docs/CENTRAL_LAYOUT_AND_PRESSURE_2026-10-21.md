## 运动模块修复

1. `ArmController::PlanTransitWithApproach()` 新增可选 `required_lift_z`。
2. 每个抓取候选仍验证原本的悬停→接触下降路径。
3. 由下降轨迹的末端关节状态重建接触时机器人状态，再做完整的接触→安全高度 Cartesian 规划。
4. 只有整段比例≥0.999、轨迹非空、每个关节采样都满足既有关节余量时，该姿态候选才有资格进入自由空间转移路径评分。
5. 不通过的候选在执行转移、接触、闭合夹爪之前拒绝。整个检查只规划，不执行；不会关闭碰撞检查来强行运行。
6. `RaiManipulationInterfaceNode` 声明 `post_grasp_lift_z_m` 参数，只有 grab 阶段传入该预检高度。
7. 启动文件从同一工作站 YAML 读取高度传给 C++ 节点，与工作站真正发送 lift Action 的高度一致，避免 Python 与 C++ 各自维护不同常量。
8. Action 消息类型未改，原来的 grab/lift/place/retreat 分阶段执行保留；预检通过不是宣告真实抓放完成，实际动作仍需反馈与装箱验证。

## Agent 计划格式鲁棒性

- 先前真实预试验出现过一次未返回恰好一个计划提案，导致运动前失败。
- `ProduceAgent.plan_order()` 对错误调用数量、工具名、JSON 和计划结构做最多三次校正请求；每次仍按同一上下文与剩余需求严格校验。
- 记录 AGENT_PLAN_REJECTED 的次数、原因类别和工具调用名称，不记录私密模型正文或 Key。
- 不重试物理动作，不用脚本计划替代模型，不自动替换模型。网络/鉴权异常仍向上传播。
- 重试期间不调用工作站的物理工具；校正用例与三次耗尽用例已添加。
