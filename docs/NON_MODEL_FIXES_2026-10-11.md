# 非模型链路修复与验证

## 本次范围

不更换 GroundingDINO、SAM 或 Agent 模型，不修改检测置信度阈值，不以仿真已知坐标替代视觉目标，不关闭碰撞检查。本次集中处理已定位的库存/候选、RGB-D 输入、规划搜索、布局可达性与失败恢复问题。不能将小样本通过解释为“所有非模型问题永久消失”。

## 联动关系及改动

### 1. 感知输入 → 点云 → 工作站候选

主项目 `rai_perception/components/gripping_points.py` 中的 `PointCloudFromSegmentation` 增加可选 RGB-D 时间差检查。工作站启用 `max_rgb_depth_skew_s: 0.1`。

获取图像后，在模型推理之前，短时重新读取较旧的数据流，直到时间差符合要求；仍不匹配或 RGB/深度尺寸不同就明确报错，不生成三维坐标。诊断记录两个图像时间戳。这是有界重新取样与一致性检查，**不是**基于缓冲区的精确 message_filters 同步器。相机固定且深度已对齐是当前方案前提。

### 2. 工作站候选 → 库存预留 → Agent 选品

原问题：订单要一件时，`get_object_positions` 只返回那一件预留对象，图中其它空闲候选被隐藏，Agent 选错之后被迫重复检测。

现在返回该订单已预留候选和同帧可选空闲备选。备选不是额外库存承诺。`InventoryLedger.select_for_order` 在锁内选定目标：必要时交换该订单一件未执行的 RESERVED 资源；不超过订单需求，不释放 CARRYING/UNKNOWN，不偷其它订单的预留，对重叠锁定身份也拒绝。类别安全核验仍先于抓取。

`reserve` 刷新坐标使用配置半径，不再另外硬编码 6.5 cm。

### 3. 已选候选 → 机械动作 → 库存确认

`InventoryLedger.begin_execution` 增加执行期间锁定：RESERVED 目标正在抓取时不因视觉 TTL 过期而变成 UNKNOWN。仍需抬升验证通过才进入 CARRYING；放置核验通过才进入 PLACED，解除执行锁。失败、取消、明确的抓取规划拒绝会清理执行锁，并按安全状态处理库存。

这是“执行中保护”，不是延长整桌过期库存，也不是提前宣称抓取完成。

### 4. 抓取规划 → Action 结果 → 选择其它候选

`ExecuteMotion.action` 结果增加 `safe_to_reselect`。C++ 服务端只在以下条件全部满足时返回 true：

- 动作为 grab；
- 最后阶段是 PLANNING_TRANSIT；
- 返回明确的转运/接近规划失败；
- Action 没有被取消，没有执行抓取转运、最终接近或关闭夹爪。

初始打开夹爪和安全抬升可能已经完成，但还未接近/抓起商品。转运/接近执行失败、超时、取消、lift/place 等绝不适用。

Python `Workstation.move` 将该结果映射为 `MotionPlanRejected`；`pick_and_place` 解除该目标执行锁、记录 MOTION_PLAN_REJECTED、进入有界换候选流程。订单服务器以 `physical_state_uncertain` 决定是否需要恢复，不再只凭“尝试过动作”锁死整个工作台。其它执行错误仍保守进入恢复。

### 5. 布局 → MoveIt 碰撞场景 → 规划器

增加只读 `scripts/inspect_collision_snapshot.py`：把失败诊断中的关节样本逐一送入 `/check_state_validity`，输出碰撞双方，不执行轨迹。

此前玉米失败的诊断轨迹，15 个样本中后面 11 个与返筐碰撞，涉及 panda_link5/6/7。问题是返筐恰好占据了玉米接近时腕部/前臂所在空间，并非只有“转运时绕开”的需求。

将物理返筐与规划配置同步从 x=0.43 移至 x=0.26、y=0 的桌面内侧；保持真实返筐模型、五块碰撞代理、尺寸和 padding 不变。不是只移动不可见代理或删掉障碍。新场景同一批 15 个关节样本全部通过当前场景检查，第一件玉米实际完成了抬升和装箱。

`ArmController::PlanTransitWithApproach` 交替执行“悬停 IK → 向下验证”和“接触 IK → 反向验证”搜索，避免 12 秒预算先被前一组耗尽；每个候选仍经过完整 Cartesian 碰撞检查、关节边界与轨迹代价筛选，不执行用于诊断的不检查碰撞的轨迹。

### 6. 已验证放置 → 空手观察姿态 → 下一次检测

混合订单实测时苹果检测原始框、掩码、点云、坐标均为 3，说明这一次不是后处理删掉正确目标。真实相机快照 `inspection-1791692144550403750.jpg` 显示机械臂和前方已完成订单箱造成遮挡。只让空手机械臂回到启动时记录的关节姿态，不改变商品、箱子、模型或阈值，然后复查：苹果原始框增加到 5，重新出现右侧两个真苹果候选。这是一次观察姿态对照，不是模型性能统计。

配置 `motion.return_to_observation: true`，工作站在已验证放置后的下一次视觉定位/库存扫描之前，调用现有 `/reset_manipulator` 服务。服务经 MoveIt 规划到启动时记录的关节目标，不重置桌面、订单、箱子或库存。只允许物理状态明确且没有执行中抓取时进行；失败/超时仍标记物理不确定。这个服务不支持 Action 式取消，取消请求会在这段有界动作完成后检查，不在半路强行重发运动。

已完成订单箱仍保留等待取货，所以观察姿态不能保证消除箱子本身遮挡。不能把这一步宣传为“视觉漏检全解决”。

## 剩余边界

开放词汇检测仍可能混淆苹果和番茄；空间关联仍不是可靠外观跟踪；本轮不是长期可靠性或漏检率统计。硬件掉线、任意未知布局和真实机器人反馈替代也不在“全部已解决”的结论中。

诊断与测试脚本均位于 `ros2_ws/src/produce_order_workstation/scripts/`；真实测试报告保存在 `~/.local/share/produce_order_workstation/reports/`。以后换模型时应先保持这一套业务/执行契约不变。
