# 颜色复核与启动入口修复

## 一、改了什么

- 新增 `color_verification.py`，在原有视觉组件上增加适配层，不修改 RAI SDK 源码。
- 原流程保留：GroundingDINO 检测 → SAM 分割 → 深度点云 → TF → 三维位置。
- 新增位置：SAM 返回掩码之后、深度点云计算之前。
- 只接受物体分割区域内的颜色；腐蚀一圈边缘，排除桌面背景、低饱和度、深阴影与高光。
- 用 HSV 色相/饱和度判断当前偏棕苹果与鲜红番茄素材；不会读取实体名称、生成位置、订单数量或“应该有四个”的先验补结果。
- 提示 apple 时只保留颜色证据支持 apple 的掩码；提示 tomato 同理。证据不足或矛盾就拒绝，不取前四个、不放宽跨类别冲突保护。
- 玉米、胡萝卜和其他未配置的商品继续走原有视觉流程。
- 保留抓取前的仿真安全核对；颜色复核不替代抓取结果验证。

## 二、规则与实际校准

- 配置：`config/workstation.yaml` → `perception.color_verification`。
- `enabled`：是否启用；可关闭做对照。
- `profile: brown_apple_red_tomato`：明确限定当前素材，不是通用水果分类器。
- OpenCV HSV 的 H 范围为 0–179，S/V 范围为 0–255。
- 棕色证据：H 8–30，S 60–170。
- 红色证据：H ≤10 或 H ≥170，且 S ≥175。
- 至少 50 个有效像素，颜色支持率至少 0.52，且超过另一类至少 0.20；空、小、异常大、无明显颜色或混合证据的掩码不通过。
- 第一轮实际 SAM 掩码中，苹果棕色支持率约 0.54–0.61，而番茄棕色支持率低于 0.06。初始 0.55 阈值漏掉一颗苹果；基于这组掩码证据校准到 0.52，并保留多数支持与差值条件。
- 不同光照、换素材、真实红苹果可能不适用，需要重新验证或关闭该 profile。不能将颜色当成普适类别真值。
