# 轨迹观感优化：从“可行”到“优选”

本文记录首轮 `bb74c08` 的优化；后续用户指出摆幅仍大，实测和进一步修改见 [关节摆幅排查（尚未解决）](JOINT_EXCURSION_FIX.md)。当前评分额外包含最大关节摆幅，抓放转移支持吸盘轴向朝向选择。

用户观察到能完成订单，但机械臂大幅伸展、转腕，路线不自然。此前碰撞修复只解决路径是否可行：随机 IK 搜索到第一组可行解即执行，没有比较不同肘部姿态和路径长度。七自由度机械臂的末端目标相同，关节姿态却可能差别很大。

## 改动

`ArmController::PlanTransitWithApproach` 改为最多八个 IK 种子：当前姿态、两个邻近肘部种子、五个随机种子。只有避碰 IK 和完整正反向接近均通过的候选才能参加比较；无下降的转移段也使用同一候选策略，但不施加下降余量。

1. 相对当前状态计算加权关节距离，末端腕关节权重为 2，惩罚大幅转腕。Panda 是有界关节，不把接近一圈的转动当作“短角度”。
2. 剔除近乎相同的候选，按关节距离排序。
3. 对最近的最多三个候选分别运行 OMPL，每次规划时间设为 3 秒；规划完恢复原 5 秒设置。
4. 用 `path_length + 0.5 * posture_distance` 比较成功轨迹，选择分数最低的一条。路径长度指加权关节空间长度，不是末端在桌面上的直线距离。
5. `PlanFreeSpaceToPose` 也委托给该策略，所以不仅抓取上方转移，装箱转移也优选关节姿态。
6. 速度缩放从 1.0 降至 0.35，加速度从 1.0 降至 0.25，作用于 MoveIt 轨迹时间参数；不是修改机械臂最大硬件限制，也不是把速度降低就称为路径已改善。

评分计算在 `robotic_manipulation/include/robotic_manipulation/motion_preferences.h`，新增两个 GTest 覆盖大幅腕部转动、绕路与非法数据；原状态稳定保护测试仍保留。新日志打印每条规划的 posture/path/cost 和最终选择，便于核对。

碰撞检查、完整 Cartesian 要求、附着商品碰撞体和执行前状态检查全部保留。局部下降、抬起、退离仍是 Cartesian，不能为视觉观感而改成穿过桌面商品的任意自由路径。

## 边界

这是一种有限候选的优选，不保证全局最短，也不是 jerk 限制的专门平滑器。避障导致的必要绕路仍会保留。多候选规划会增加规划等待时间，调低速度会增加执行时间；需要实际订单检验运动 Action 的超时余量。

速度设置对 Cartesian 的传递已核对 [MoveIt Jazzy 官方实现](https://github.com/moveit/moveit2/blob/jazzy/moveit_ros/planning_interface/move_group_interface/src/move_group_interface.cpp)：MoveGroupInterface 将速度/加速度缩放写入 GetCartesianPath 请求，也写入自由规划请求。
