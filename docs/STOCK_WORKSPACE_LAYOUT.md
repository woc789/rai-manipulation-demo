# 备货工作区调整与运动复测

## 本次改变的是什么

用户允许改变物品初始分布。基线为 `83e7225`，本次不改变其 C++ 规划/执行逻辑、速度/加速度、抓取高度、箱位或障碍物。仍保留每类四件、共十六件混合库存。

旧场景有商品位于 `(0.22, -0.12)` 等底座附近位置。上一轮在实际下降候选中记录到 `panda_link1` 与 `panda_link5` 自碰撞；并不能据此声称所有大摆幅都是障碍箱引起。本轮将库存移到两侧备货区，中心通道留空，验证工作区是否更适合机械臂使用。

### 场景配置 → 布局检查 → 仿真生成

1. `config/demo_scene.yaml`：只调整十六个 `stock_*` 实体的 XY。玉米仍横放，四类混合分布，不按订单逐件生成。靠近中心的两列是 X=0.30/0.41 m；靠近外侧箱位的两列收窄到 X=0.23/0.34 m。Y 分布在 ±0.26、±0.35、±0.44、±0.53 m。
2. `config/workstation.yaml` 的 `stock.layout`：设置基座径向距离至少 0.39 m、库存中心间距至少 0.085 m、距各未来箱位中心至少 0.14 m。原来的 `(0.22,-0.12)` 距基座约 0.251 m，新配置的最小距离约 0.397 m。
3. 新增 `stock_layout.validate_stock_layout(scene, config)`：输入 `SceneConfig` 和工作站配置，检查上述距离、工作区边界、有限坐标和每类库存数量。成功不返回数据，失败抛出 `OrderError`。这些只是几何配置规则，**不是完整 IK 可达性或碰撞无风险的证明**。
4. `Workstation.prepare_scene()`：在清除旧实体前先载入、检查新配置；配置不合法时不删除旧场景。通过后仍由 `O3DExROS2Bridge` 调用 ROS 生成服务生成实体，等待物理稳定，测量实体并同步 MoveIt PlanningScene。

规则使用当前 demo 的 world/panda_link0 对齐假设。未来若改变机器人底座变换，需要先通过 TF 转到同一参考系，不能直接复用 XY 数字判断距离。中心距离规则也不是精确网格碰撞检查；真实生成、抓取和放箱仍要接受后续物理/运动审计。

### 下单 → Agent 感知 → 运动执行没有替换

初始化配置里的生成坐标没有进入 Agent 的物体位置返回值。Agent 仍调用 `get_object_positions`：RGB-D 图像 → 检测/分割 → 深度三维投影 → TF 变换到 panda_link0。运动工具仍使用本次视觉位置，经工作站校验后发送 `ExecuteMotion` Action。

`RaiManipulationInterfaceNode` 仍编排抓取/抬起/装箱/退离，`ArmController` 仍调用 MoveIt IK、Cartesian 与 OMPL 规划，经过起点检查后执行轨迹。障碍物碰撞体、附着物体、抓取与放箱审计没有关闭。

## 如何验证

- 新增布局测试：合法十六件、底座附近、箱位占用、越界、非有限坐标、重叠、缺库存、删除旧场景前拒绝错误配置。
- 一个旧测试只模拟旧式障碍和箱子，用于检查 MoveIt 不可用时必须停止；仅在该测试的局部配置关闭库存布局规则，生产配置保持启用。
- 真实订单通过公开 `/produce_orders/execute` Action 提交；使用配置的 Agent 和视觉工具，不直接发生成位置抓取。
- `/joint_states` 报告同时记录各运动阶段、整件物品和整单的最大/最小关节角与角度路程。不能用单段改善来掩盖整件摆幅。

本轮后端测试 94 项、Qt 界面测试 9 项通过。不同分布的比较是工作区干预效果，不是同一坐标条件下的规划器性能提升。

报告路径：`~/.local/share/produce_order_workstation/reports/<order_id>.json`，对应关节反馈在 `reports/motion/<order_id>.json`。样本来自 BEST_EFFORT 订阅，可能丢包；采样范围不是连续时间的精确极值。
